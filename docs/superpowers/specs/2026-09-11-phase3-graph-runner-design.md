# phase3 설계 — 전략 그래프 러너 (데모 앱)

작성일: 2026-09-11
상태: 승인됨 (구현은 발표 후 착수)

## 배경

phase3 문서(9장)와 검증 테스트 19개는 완성됐다. 발표용으로 만든 화면 목업
"전략 그래프 러너"(아티팩트)가 흐름 승인을 받았다: 전략 그래프를 그려 두고,
실행이 지나가는 노드·엣지를 점등하며 콘솔에 이벤트를 흘리는 화면.

목업은 이벤트가 시뮬레이션이다. 이 설계는 그것을 실물로 승격한다 —
**진짜 Koog 에이전트 실행이 그래프를 점등**시킨다.

## 왜 이 데모인가

- 발표에서 시연한 화면의 "진짜 버전"이라 서사가 이어진다
- Koog의 이벤트 훅(EventHandler feature)이 실행을 관측 가능하게 만든다는
  1장 주장의 실증 — 데모 자체가 학습 자료가 된다
- phase2 데모(21패턴 나열)와 달리, Koog가 실제로 바꾸는 패턴만 보여준다

## 범위

**포함** — 시나리오 4개:

| 시나리오 | 전략 출처 | 화면에서 보이는 것 |
|---|---|---|
| 라우팅 | Ch04 "조건 엣지가 분기를 고른다" | 조건 엣지가 갈리는 순간 |
| 도구 루프 | Ch05 "도구 호출 왕복을 그래프로" | request→execute→report 왕복 |
| 메모리 | Ch06 평문-only 검증 | 실행 후 저장소 행 스냅샷 — 도구 턴이 없는 것 |
| MCP | Ch08 | phase2 서버 도구 목록·실호출 (서버 없으면 비활성 표시) |

**제외**: 21패턴 전체 재현, 구조화 출력(phase4), 인증·멀티유저, 실행 이력 저장.

## 아키텍처

```
demo-phase3 (main 소스로 확장, 테스트·문서는 불변)
├── runner/                    시나리오 서비스 + SSE
│   ├── RunnerController        GET /api/scenarios · POST /api/run/{id} (SSE)
│   ├── RunEvent                {type: node|edge|tool|log|answer|done, …}
│   └── scenarios/              시나리오 4개 (전략 + 그래프 메타)
└── static/index.html          목업 이식 — 시뮬레이션 제거, SSE 구독
```

- **이벤트 소스**: Koog EventHandler feature(`handleEvents`)를 1순위로.
  도구 이벤트(onToolCallStarting 등)는 공식 문서에 있고, **노드 수준
  이벤트 존재 여부가 미확정** — 스파이크가 판정한다. 노드 훅이 없으면
  폴백: 전략 노드 람다 안에서 이벤트 채널로 직접 발행(래퍼 노드).
- **전략 코드는 main에 복제한다.** 테스트의 전략을 옮기지 않는다 —
  문서 코드 블록이 테스트에서 복사됐으므로 테스트·문서는 동결이 원칙.
  중복은 의도된 비용.
- **그래프 메타(노드 좌표·엣지)는 서버가 시나리오와 함께 내려준다** —
  화면과 전략이 어긋나지 않도록 한 곳에서 정의.

## 기술 전제

- demo-phase3 스택 그대로: Kotlin 2.2.21 · Boot 3.5.14 · Spring AI 1.1.6 ·
  Koog 1.2.0(브리지·MCP 모듈 1.2.0-beta) · Kotest 5.9.1
- SSE는 Spring MVC `SseEmitter` (의존성 추가 없음)
- 발표 안정성: `spring.ai.ollama.chat.options.keep-alive` 검토(phase2 교훈)

## 리스크

1. **EventHandler의 노드 수준 이벤트 미확정** — Task 1 스파이크로 판정,
   없으면 래퍼 노드 폴백(설계에 이미 반영)
2. suspend 실행(agent.run)과 SseEmitter의 스레드 경계 — 코루틴 스코프에서
   실행하고 emitter로 브릿지, 스파이크에서 함께 확인
3. MCP 시나리오는 외부 서버 의존 — 프로브로 비활성 처리(테스트 Ch08과 동일 패턴)
