# phase2 방향 & 결정 로그

phase2(로컬 LLM 연동)를 진행하며 내린 결정과 근거를 남긴다.
본문에는 들어가지 않는 "왜 이렇게 했나"의 기록.

상세 설계는 [2026-09-04 설계 문서](../superpowers/specs/2026-09-04-phase2-local-llm-design.md).

---

## 목표

phase1이 설명만 하고 검증하지 않은 **이식성**을 실물로 시험한다. 상용 프런티어 모델(Anthropic)에서 로컬 오픈 모델로 내려갔을 때 **무엇이 그대로 돌고 무엇이 깨지는지**를 관측한다.

궁극적으로는 사내 로컬 LLM 연동이 목표이고, phase2는 그 1단계다.

## 결정 사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 주제 | 로컬 LLM 연동 | phase1의 1번 테마(이식성)를 회수. 사내 도입이라는 실제 목표의 1단계 |
| 상용 API 의존 | **전면 제거** | 참여자가 키 발급 없이 clone→실행. phase1은 각자 `ANTHROPIC_API_KEY`가 필요했다 |
| phase1 데모 | **그대로 보존** | `demo-phase1/` 로 남긴다. phase1 문서의 코드 매핑표가 계속 유효하고, 발표에서 되돌아갈 수 있다 |
| 코드 배치 | phase마다 **독립 Gradle 프로젝트** | `demo-phase1` · `demo-phase2`. 서로 의존하지 않아 한쪽을 고쳐도 다른 쪽이 깨지지 않는다 |
| 모델 전환 | **런타임 옵션**(요청마다 지정) | 프로필 전환은 재시작이 필요해 비교 실습에 부적합 |
| 핵심 화면 | 같은 요청 × 모델 N개 격자 | "어디서 무너지는가"는 나란히 놓고 보는 편이 빠르다 |
| 모델 구성 | qwen3:1.7b · qwen3:8b · granite3.3 · glm4:9b | 크기 축(1.7b↔8b)과 계열 축(qwen↔granite)을 동시에. glm4는 도구 미지원 대조군 |
| 사실성 | phase1과 동일 — 팩트 기반만 | 모델 거동은 **관측 결과만** 적는다. 예상은 study-log에 "예상"으로 명시 |

> **방향 전환 이력 — 코드 배치**
> 처음에는 데모를 하나로 두고 프로필로 벤더를 바꾸려 했다. "같은 코드가 다른 모델에서 돈다"를 구조가 직접 보여준다는 이유였다.
> 그러나 phase2 가 상용 API 의존을 전면 제거하면서 그 논증은 데모 하나 안에서 성립하지 않게 됐다 — Anthropic 이 빠진 이상 한 프로젝트에서 비교할 두 벤더가 없다. 이식성은 **포터블 `ChatOptions` 로 모델을 갈아끼우는 것**으로 phase2 안에서 이미 증명된다.
> 반면 데모를 합치면 phase1 예제가 사라져 그 문서의 코드 매핑이 죽는다. 잃는 것이 더 커서 독립 프로젝트로 분리했다.

## 관통 테마 (phase1에서 이어짐)

- **이식성** — phase1은 벤더 교체를 설명했고, phase2는 그 한계선을 잰다
- **위임 vs 통제** — 모델이 약할수록 통제가 더 필요해진다. 가드레일의 필요성이 로컬에서 더 선명해진다
