2부 실행 · 가장 작은 에이전트

AIAgent 해부 — 다섯 줄이면 돈다 공식 문서와 다름

val agent = AIAgent(
    promptExecutor = promptExecutor,  // 브리지가 준 빈
    llmModel = KoogModels.QWEN3_4B_INSTRUCT,
    systemPrompt = "한 문장으로만 답한다.",
    temperature = 0.2,
    maxIterations = 5,
)
val result = agent.run("2 더하기 3은?")   // suspend
// 실측 응답: "5"
  • AIAgent(...)는 생성자가 아니라 팩토리 함수 — GraphAIAgent를 돌려준다 (문서엔 없고, 컴파일 오류로 확인)
  • run()은 suspend fun run(agentInput, sessionId = null) — 코루틴 밖에서 부르면 컴파일이 거부
  • qwen3:4b는 프리셋이 없어 LLModel(provider, id, capabilities)로 직접 정의
공식 docs.koog.ai — Basic agents 실측 Ch03SingleAgentTest (2회 독립 실행 동일 출력) · 3장 — 시그니처는 컴파일러 오류 원문으로 채증

2부 실행 · Koog의 정체성

전략 그래프 — 흐름이 선언이 된다 공식 예제는 컴파일 안 됨

val router = strategy<String, String>("route") {
    val classify by nodeLLMRequest()
    val math  by node("math")  { "수학 경로" }
    val other by node("other") { "일반 경로" }

    edge(nodeStart forwardTo classify)
    edge(classify forwardTo math
        onTextMessage { "MATH" in it.text })
    edge(classify forwardTo other
        onTextMessage { true })
    edge(math forwardTo nodeFinish)
    edge(other forwardTo nodeFinish)
}
  • 엣지는 선언 순서대로 검사, 첫 매치가 이긴다 — 라우팅 테스트가 실증
  • 공식 문서 예제는 그대로 컴파일되지 않는다 — nodeLLMRequest 출력은 Message.Assistant라서 textContent() 변환이 필요
  • 루프 상한을 넘기면 멈추는 게 아니라 MaxNumberOfIterationsReached 예외

▶ 여기서 화면 전환 — 전략 그래프 러너 라이브 시연 (라우팅 → 도구 루프 → MCP)

3부 경계 · 문서 밖에서 찾은 것들

MCP는 됐다 — 문서에 없는 길로 javap로 발굴

phase2 데모가 MCP 서버가 되고, Koog 에이전트가 클라이언트로 붙어 lookupOrder를 실제 호출했다. 단, 공식 문서는 stdio·SSE만 적어 두었고 — STATELESS 서버에 붙는 streamableHttp는 jar 안에만 있었다.

4부 판단 · 그래서 쓸 것인가

손익 — 공짜로 받는 것과 떠안는 것

받는 것

  • 흐름이 그래프 선언이 된다 — 분기·루프·도구 왕복이 코드 밖으로
  • 히스토리 압축·재시도·상태 복원·관측성이 설치형 기능
  • 기존 Spring AI 빈·Ollama 설정 재사용 — 서빙 인프라 무변경
  • Kotlin 네이티브: suspend·타입 안전 DSL

떠안는 것

  • Spring AI 2.x 미지원 — 브리지 쓰려면 1.1.6/Boot 3.5로
  • 브리지·MCP 모듈은 아직 beta 트랙
  • 메모리 어댑터의 평문-only — 도구 이력 감사는 불가
  • 문서와 실물의 간극 — 예제 미컴파일, 미기재 API, 빈 충돌

운영 기준의 결론: 신규 Kotlin 서비스엔 지금도 매력적, Spring AI 2.x 기반 기존 서비스엔 브리지 정식화까지 관망. 미확인 8개 — 특히 구조화 출력 — 이 다음 스터디다.
