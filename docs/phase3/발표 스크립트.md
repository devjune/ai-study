# Koog 세미나 발표 스크립트 (15분)

슬라이드 12장 기준. 괄호는 목표 시간, 꺾쇠는 행동. 대본 합계는 약 12분, 나머지는 여유분.

---

## 1. 표지 (10초)

JetBrains가 만든 JVM 에이전트 프레임워크, Koog를 소개합니다.

## 2. 목차 (15초)

앞 4분은 Koog가 뭔지. 본론 6분은 미니 하네스 하나를 다섯 단계로 만들어 봅니다. 데모 보고 마무리합니다.

## 3. 소개 (50초)

〈타임라인〉 에이전트 프레임워크는 파이썬이 먼저입니다. 2022년 LangChain.

JVM은 2023년 LangChain4j가 받았습니다. 스스로 "idiomatic Java"라고 소개합니다. Kotlin 네이티브는 아니라는 뜻입니다.

그 자리를 2025년 Koog가 채웠습니다. 작년 5월 1.0, stable 모듈은 1년 호환 보장입니다.

## 4. 왜 만들었나 (40초)

〈인용문〉 README 첫 줄입니다. 예측 가능, 장애 허용, 엔터프라이즈.

JetBrains가 Junie와 AI Assistant를 Kotlin으로 만들며 다듬은 방식을 공개한 겁니다.

공식 예제가 용도를 말해 줍니다. 문의 분류, 도구 호출, 외부 시스템 제어, 운영 모니터링.

## 5. 기능 범위 (30초)

〈지도 전체〉 공식 문서 목차 전부입니다. 넓습니다.

〈검은 칩들〉 칠한 칩이 오늘 만들 미니 하네스가 쓰는 기능입니다. 이 일곱 개로 하네스 하나가 됩니다. 나머지는 자료로 공유합니다.

## 6. 오늘 만들 것: 미니 하네스 (40초)

모델 호출만 하면 Spring AI로 충분합니다. 그 이상이 언제 필요한지, 비서 하네스를 다섯 단계로 만들며 확인합니다.

〈단계 맵〉 에이전트, 도구, 스킬, 라우팅, 시각화.

## 7. 1/5 기본 에이전트 (40초)

〈코드〉 AIAgent 하나와 입력 루프면 REPL이 됩니다.

핵심은 promptExecutor. 모델 호출을 맡는 Koog 인터페이스인데, Spring AI로 치면 ChatModel 자리입니다. Koog가 배포하는 Spring AI 연동 스타터, 줄여서 브리지가 ChatModel을 감싸 빈으로 등록해 주고, 모델 설정은 기존 properties 그대로입니다.

〈터미널 1: koog step1〉 "2 더하기 3은?" → 5. 이게 전부입니다.

## 8. 2/5 도구 (50초)

비서니까 일정을 보게 합니다. 〈코드〉 함수에 @Tool, 설명은 애노테이션으로. 하네스에는 레지스트리 한 줄.

JSON 스키마를 적지 않았습니다. 시그니처가 곧 스키마입니다. 파라미터를 더하면 서술자도 따라 바뀝니다. 도구 왕복은 기본 전략이 처리합니다.

〈터미널 2: koog〉 "내일 일정 알려줘" → 도구를 부르고 결과만 답합니다.

## 9. 3/5 스킬 (50초)

이번엔 능력을 파일로 꽂습니다. 〈frontmatter〉 스킬은 마크다운 파일 하나입니다. description 목록이 에이전트의 스킬 카탈로그가 됩니다.

요청이 스킬에 해당할 때만 파일을 읽어 지침을 따릅니다. 프롬프트에 미리 싣지 않습니다.

〈터미널 2 그대로〉 "판교 사투리 11로 바꿔 줘: 내일 회식 오세요" 〈출력을 잠시 읽게 둔다〉

## 10. 4/5 라우팅 (60초)

하네스가 커지면 분기가 필요합니다. Koog에서 분기는 if문이 아니라 엣지 선언입니다. 이 edge 줄은 실행문이 아니라 그래프라는 자료구조를 만듭니다. 값이니까 실행 전에 만져볼 수 있습니다.

규칙: 적은 순서대로 검사하고 먼저 맞은 하나만, true 엣지가 else 자리. 타입이 맞아야 엣지가 붙고, 연결 오류는 컴파일에서 거절됩니다.

단, 분기 누락은 컴파일러가 모릅니다. when과 다른 점이고, 오늘의 트레이드오프입니다.

## 11. 5/5 시각화 (30초)

〈다이어그램〉 방금 그 라우팅 전략에 asMermaidDiagram() 한 번. 코드에서 나온 그림이라 코드가 바뀌면 그림도 바뀝니다.

분기 선언도, 타입 검사도, 이 그림도 전부 전략이 자료구조라서 얻는 겁니다.

## 12. Demo (2분 + 질의)

〈터미널 2 그대로〉 아까 그 대화가 이어지는지 봅니다.

입력: "방금 말한 첫 번째 일정이 뭐였지?" → 10:00 팀 싱크 (챗 메모리).

청중 즉흥 입력 받기 (↑ 화살표로 이전 입력 재사용).

한 마디: 4B 로컬 모델은 성격이 다른 도구 둘을 섞으면 헛짚어서, 요청을 갈라 전담 에이전트 둘에 넘겼습니다. 분기가 필요해지는 순간이 바로 4단계의 그 자리입니다. 작은 모델일수록 프롬프트보다 구조입니다.

질문 받고 마무리. 자료와 코드는 공유.

## 준비 체크리스트

- 모델 웜업 + 2시간 고정 (발표 직전 1회):
  `curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null`
- 터미널 두 개를 미리 띄워 웜업 질문 한 번씩: 터미널 1 `koog step1`, 터미널 2 `koog`
  (명령 설치 위치는 /opt/homebrew/bin/koog. 내부에서 bootJar 후 jar 실행)
- 데모 입력 네 개는 복사해 둘 것 (2 더하기 3 / 내일 일정 / 판교 사투리 / 첫 번째 일정)
