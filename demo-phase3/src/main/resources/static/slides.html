01

왜 만들었나

"Koog is a JVM (Java and Kotlin) framework for building predictable, fault-tolerant and enterprise-ready AI agents" 예측 가능하고 장애를 견디고 기업 환경에서 쓸 수 있는 에이전트

JetBrains 내부에서 먼저 사용

  • IDE의 코딩 에이전트 Junie와 AI Assistant를 Kotlin으로 개발 중
  • 거기서 다듬은 방식을 프레임워크로 묶어 공개
  • Junie가 Koog로 만들어졌다는 공식 확인은 없음

공식 예제

  • Banking: 문의 분류와 도구 호출
  • Chess: 반복 대국 진행
  • GoogleMaps · Playwright · Unity: 외부 시스템 제어(MCP)
  • OpenTelemetry · Langfuse · Weave: 운영 모니터링

03 미니 하네스

오늘 만들 것: 미니 하네스

  • 모델 호출만 필요하면 Spring AI로 충분. 그 이상이 필요해지는 지점을 확인하는 것이 목적
  • 작은 하네스를 다섯 단계로 만들며, 단계마다 Strategy Graph의 설계를 하나씩 확인
1단계기본 에이전트AIAgent 다섯 줄과 REPL
2단계라우팅타입 검사를 통과한 엣지와 조건 분기
3단계히스토리노드 사이에 공유되는 대화 기록
4단계반복 상한무한 루프 대신 예외
5단계시각화전략에서 생성되는 다이어그램
DSL이 아니라 그래프가 핵심. DSL은 그래프를 코드처럼 읽히게 하는 포장

사전 정의 전략, 병렬 노드, 서브그래프, 커스텀 노드는 오늘 다루지 않음.

03 미니 하네스 · 1단계

기본 에이전트: 다섯 줄과 REPL

추가: AIAgent 다섯 줄 · 확인: REPL 응답 "5"

val agent = AIAgent(
    promptExecutor = promptExecutor,   // Spring AI 브리지가 만든 빈
    llmModel = KoogModels.QWEN3_4B_INSTRUCT,
    systemPrompt = "짧게 답한다.",
)
while (true) { print("❯ "); val line = readLine() ?: break; println(agent.run(line)) }
$ ./gradlew bootRun --args='--spring.profiles.active=harness'
❯ 2 더하기 3은?
5

구성

  • AIAgent 하나로 에이전트 생성. 전략을 안 적으면 기본 전략으로 동작
  • promptExecutor는 브리지가 만든 빈. 모델 설정은 기존 application.properties 그대로
  • 여기까지는 단일 호출. 다음 단계부터 흐름 제어를 추가
실측 Harness.kt: bootRun REPL에서 "5" 출력 · REPL: 한 줄씩 읽어 실행하고 출력을 반복하는 대화형 루프 (Read-Eval-Print Loop)

03 미니 하네스 · 2단계

노드와 엣지: 타입이 붙은 자료구조

추가: 노드 연결 · 확인: 컴파일 거절 메시지

val draft  by nodeLLMRequest()
val polish by nodeLLMRequest()

edge(draft forwardTo polish)              // ✕
edge(draft forwardTo polish
    transformed { it.textContent() })    // ○
None of the following candidates is applicable:
fun <…, CompatibleOutput : OutgoingInput> edge(…)

여기서 알 수 있는 것

  • nodeLLMRequest()의 출력은 문자열이 아니라 메시지 타입
  • 앞 노드의 출력과 뒤 노드의 입력, 타입이 맞아야 엣지가 붙음
  • 안 맞으면 컴파일 단계에서 거절. 거절 사유도 시그니처에 있음
  • 메시지에서 글자만 꺼낼 때 textContent() 사용
손으로 짜면 실행해 봐야 아는 오류를, 여기서는 컴파일러가 먼저 검출
진단 컴파일러 거절 메시지 원문 · 실측 StrategyGraphTest

03 미니 하네스 · 2단계

조건 엣지: 분기가 선언으로

추가: 조건 엣지 2줄 · 확인: 4회 모두 "일정 경로"

val router = strategy<String, String>("route") {
    val classify by nodeLLMRequest()
    val schedule by node("schedule") { "일정 경로" }
    val other    by node("other")    { "일반 경로" }

    edge(nodeStart forwardTo classify)
    edge(classify forwardTo schedule onTextMessage { "SCHEDULE" in it.text })
    edge(classify forwardTo other onTextMessage { true })
}

평가 규칙

  • 엣지는 적은 순서대로 검사
  • 먼저 맞은 하나만 적용
  • { true } 엣지가 마지막 받침이 됨. when의 else 자리
  • 분기를 빠뜨려도 컴파일러는 모름. when과 다른 점

조건 세 종류

onCondition필터
onTextMessage필터 + String 변환
onToolCalls도구 호출 응답으로 한정
실측 StrategyGraphTest 라우팅. 4회 돌려 모두 "일정 경로"

03 미니 하네스 · 3단계

프롬프트 히스토리: 값이 아니라 대화가 흐름

추가: 두 번째 노드 · 확인: 응답 "15"

val draft  by nodeLLMRequest()
val polish by nodeLLMRequest()

edge(nodeStart forwardTo draft)
edge(draft forwardTo polish transformed { "그 숫자에 10을 더하면?" })
edge(polish forwardTo nodeFinish transformed { it.textContent() })

run("2 더하기 3은?")   // → "15"

왜 15가 나오나

  • polish에 넘긴 것은 새 질문 한 줄뿐
  • 그런데 모델은 "그 숫자"가 5라는 걸 알고 있음
  • 두 노드가 같은 대화 기록 위에서 돌기 때문
  • 대신 기록이 계속 쌓임. 그래서 압축 노드가 따로 있음
실측 체인 출력 "15"(4회 동일) · 진단 바이트코드: 각 노드가 appendPrompt 후 requestLLM

03 미니 하네스 · 4단계

루프와 상한: 틀릴 자리가 없는 설계

추가: 자기 엣지 루프 · 확인: 5걸음에서 예외

val step by node("step") { "$it." }

edge(nodeStart forwardTo step)
edge(step forwardTo step       onCondition { it.length < 3 })
edge(step forwardTo nodeFinish onCondition { it.length >= 3 })

AIAgent(…, strategy = loop, maxIterations = 5)
run("")   // → "..."
// 탈출 조건을 { true }로 망가뜨리면, 무한루프 대신
AIAgentMaxNumberOfIterationsReachedException:
Agent couldn't finish in given number of steps (5).

상한이 있는 자리

  • 자기 자신으로 가는 엣지가 루프
  • 횟수 상한은 루프가 아니라 에이전트 설정에 적음
  • 안 적으면 기본값 적용. 빠뜨릴 방법이 없음
  • 상한은 그래프 전체 걸음 수. 노드가 많으면 같은 값이 더 빨리 소진됨
실측 정상 루프는 셋째 바퀴에서 끝난다("...") · 진단 탈출 조건을 일부러 망가뜨려 받은 예외
