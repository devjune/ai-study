01

왜 만들었나

"Koog is a JVM (Java and Kotlin) framework for building predictable, fault-tolerant and enterprise-ready AI agents" 예측 가능하고 장애를 견디고 기업 환경에서 쓸 수 있는 에이전트

JetBrains 내부에서 먼저 사용

  • IDE의 코딩 에이전트 Junie와 AI Assistant를 Kotlin으로 개발 중
  • 거기서 다듬은 방식을 프레임워크로 묶어 공개
  • Junie가 Koog로 만들어졌다는 공식 확인은 없음

공식 예제

  • Banking: 문의 분류와 도구 호출
  • Chess: 반복 대국 진행
  • GoogleMaps · Playwright · Unity: 외부 시스템 제어(MCP)
  • OpenTelemetry · Langfuse · Weave: 운영 모니터링

03 미니 하네스

1/5 기본 에이전트: AIAgent 하나로 시작

추가: AIAgent와 입력 루프 · 확인: REPL 응답 "5"

val agent = AIAgent(
    promptExecutor = promptExecutor,   // Spring AI 브리지가 만든 빈
    llmModel = KoogModels.QWEN3_4B_INSTRUCT,
    systemPrompt = "짧게 답한다.",
)
while (true) {
    print("❯ ")
    val line = readLine() ?: break
    println(agent.run(line))
}
$ ./gradlew bootRun --args='--spring.profiles.active=harness'
❯ 2 더하기 3은?
5

구성

  • AIAgent 하나로 에이전트 생성. 전략을 안 적으면 기본 전략으로 동작
  • PromptExecutor는 모델 호출을 맡는 Koog 인터페이스. Spring AI로 치면 ChatModel
  • 브리지는 Koog의 Spring AI 연동 스타터(koog-spring-ai-starter-model-chat). ChatModel을 감싼 빈을 등록해 주고, 모델 설정은 기존 application.properties 그대로
  • 여기까지는 단일 호출. 다음 단계부터 도구, 스킬, 분기를 차례로 추가
Harness07.kt · REPL: 한 줄씩 읽어 실행하고 출력을 반복하는 대화형 루프 (Read-Eval-Print Loop)

03 미니 하네스

2/5 도구: 시그니처가 곧 스키마

추가: @Tool 캘린더 함수 · 확인: 도구 호출 왕복

@Tool
@LLMDescription("날짜의 일정 목록을 돌려준다")
fun schedules(@LLMDescription("날짜, 예: 내일") day: String): String {
    return "10:00 팀 싱크, 14:00 디자인 리뷰"
}

// 하네스에 한 줄
toolRegistry = ToolRegistry { tools(CalendarToolSet()) }
❯ 내일 일정 알려줘
내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.

여기서 알 수 있는 것

  • 도구는 원래 JSON 스키마로 모델에게 알려야 함. 여기서는 함수 시그니처와 설명 애노테이션이 그 스키마가 됨
  • 파라미터를 더하면 서술자도 따라 바뀜
  • 도구를 고르고, 부르고, 결과로 답을 만드는 왕복은 기본 전략이 처리

3/5 스킬: 필요할 때 읽는 SKILL.md

추가: SKILL.md + 파일 읽기 도구 · 확인: 판교 사투리 변환

---
name: pangyo-dialect
description: 평범한 한국어 문장을 판교 사투리(IT 회사 말투)로
  바꾼다. 강도 1부터 11까지. 사용자가 "판교 사투리"라고
  말하면 이 스킬을 쓴다.
---
## 강도
- 1~3: 부드러운 사내 메모 … 11: 기업 특이점
❯ 판교 사투리 3으로 바꿔 줘: 내일 회식 오세요
내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.

여기서 알 수 있는 것

  • 스킬은 frontmatter를 단 마크다운 파일. description 목록이 에이전트의 스킬 카탈로그가 됨
  • 요청이 스킬에 해당할 때만 파일을 읽어 지침을 따름. 프롬프트에 미리 싣지 않음
  • Agent Skills는 Anthropic이 낸 표준. Koog 밖에서도 통하는 형식
  • Koog 몫은 둘: 폴더에서 SKILL.md를 찾고, description 목록을 프롬프트 문자열로 만들어 줌(1.2.0-beta). 내 몫은 파일 읽기 도구를 쥐여 주는 것뿐

03 미니 하네스

4/5 라우팅: 분기가 선언으로

추가: 조건 엣지 2줄 · 확인: 일정은 캘린더로, 나머지는 모델로

val router = strategy<String, String>("route") {
    val schedule by node("schedule") { CalendarToolSet().schedules(it) }
    val answer by nodeLLMRequest()

    edge(nodeStart forwardTo schedule onCondition { "일정" in it })
    edge(nodeStart forwardTo answer onCondition { true })
    edge(schedule forwardTo nodeFinish)
    edge(answer forwardTo nodeFinish transformed { it.textContent() })
}
run("오늘 일정 알려줘")    → "10:00 팀 싱크, 14:00 디자인 리뷰"
run("오늘 점심 뭐 먹을까")  → "김치찌개, 라면, 김밥 중에서?"

평가 규칙

  • 엣지는 선언한 순서대로 검사됨
  • 넓은 조건(onCondition { true })은 마지막에 둠. 앞에 오면 뒤 분기를 가림
