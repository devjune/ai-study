# Koog 세미나 발표 스크립트 (15분)

슬라이드 12장 기준. 괄호는 목표 시간, 꺾쇠는 행동. 따옴표 안은 그대로 말하면 되는 문장.
요령: 왼쪽 코드를 위에서 아래로 손가락으로 따라가며 읽고, 오른쪽 불릿은 읽지 말고 그중 한 문장만 힘줘 말한다.

터미널 1 = `koog step1` (7장에서 한 번), 터미널 2 = `koog` (8장부터 끝까지 한 대화).

---

## 1. 표지 (10초)

"JetBrains가 만든 JVM 에이전트 프레임워크, Koog를 소개합니다."

## 2. 목차 (15초)

"앞 4분은 Koog가 뭔지 봅니다. 본론은 작은 비서 하나를 다섯 단계로 만드는 겁니다. 단계마다 코드를 보고, 바로 돌려 봅니다."

## 3. 소개 (50초)

〈타임라인 왼쪽부터〉 "에이전트 프레임워크는 파이썬이 먼저였습니다. 2022년 LangChain이고, LangGraph와 CrewAI가 뒤를 이었습니다."

〈JVM 레인〉 "JVM에는 2023년 LangChain4j가 나왔습니다. 스스로를 'idiomatic Java 라이브러리'라고 소개합니다. Java답게 만들었다는 거고, 뒤집으면 Kotlin 네이티브는 아니라는 뜻입니다."

〈Koog 상자〉 "그 자리를 2025년 Koog가 채웠습니다."

〈연혁 불릿〉 "작년 5월에 1.0이 나왔고 stable 모듈은 1년 호환을 보장합니다. 실험작 단계는 지났습니다."

## 4. 왜 만들었나 (40초)

〈인용문〉 "README 첫 줄입니다. 예측 가능하고, 장애를 견디고, 기업 환경에서 쓸 수 있는 에이전트."

〈왼쪽 칼럼〉 "말만은 아닌 게, JetBrains가 Junie와 AI Assistant를 Kotlin으로 만들면서 다듬은 방식을 묶어 공개한 겁니다. 자기들이 먼저 쓰고 내놓은 물건입니다."

〈오른쪽 예제〉 "공식 예제도 문의 분류, 도구 호출, 외부 시스템 제어, 운영 모니터링. 전부 실무 문제입니다. 그럼 안에 뭐가 들었는지 한 장으로 보겠습니다."

## 5. 기능 범위 (30초)

〈지도 전체를 쓸며〉 "공식 문서 목차 전부입니다. 넓습니다."

〈검은 칩들〉 "오늘 다 못 봅니다. 칠해진 여섯 개가 오늘 만들 비서에 들어가는 기능입니다. 나머지는 자료로 공유하고, 칩에 마우스를 올리면 한 줄 설명이 나옵니다."

## 6. 오늘 만들 것 (30초)

〈첫 불릿〉 "모델 호출만 하면 Spring AI로 충분합니다. 그 이상이 언제 필요한지 확인하는 게 오늘의 목적입니다."

〈둘째·셋째 불릿〉 "하네스는 에이전트를 감싸 돌리는 최소 실행 틀이고, 그 안에 일정과 회사 말투를 아는 작은 비서를 만들 겁니다."

〈단계 맵을 위에서 아래로〉 "기본 에이전트, 도구, 스킬, 라우팅, 시각화. 다섯 단계입니다. 시작하겠습니다."

## 7. 1/5 기본 에이전트 (50초)

〈코드 위부터〉 "AIAgent 하나 만들고, 입력 루프를 돌립니다. 이게 전부입니다."

〈promptExecutor 줄〉 "봐 주실 건 이 promptExecutor입니다. 모델 호출을 맡는 Koog 인터페이스고, Spring AI로 치면 ChatModel 자리입니다. Koog가 배포하는 Spring AI 연동 스타터, 줄여서 브리지가 ChatModel을 감싸 이 빈을 등록해 줍니다. 모델 설정은 쓰던 application.properties 그대로입니다. 기존 프로젝트 위에 그냥 얹는 겁니다."

〈터미널 1: koog step1〉 "2 더하기 3은?" → 5.

"아직 말만 할 줄 압니다. 이제 하나씩 붙입니다."

## 8. 2/5 도구 (50초)

"2단계는 도구입니다. 비서니까 일정부터 보게 하겠습니다."

〈코드 위부터〉 "평범한 Kotlin 함수입니다. 날짜를 받아 일정 문자열을 돌려줍니다. 한 일은 세 가지뿐입니다. 함수에 @Tool을 붙였고, 함수와 파라미터에 설명을 달았고, 이 함수를 ToolSet 클래스에 담아 〈아래 한 줄〉 레지스트리 한 줄로 넘겼습니다."

"도구를 모델에게 알리려면 원래는 JSON 스키마를 써야 합니다. 그런데 방금 스키마를 한 줄도 안 썼습니다. 함수 이름이 도구 이름이고, 파라미터가 스키마고, 애노테이션이 설명입니다. 시그니처가 곧 스키마입니다."

〈터미널 2: koog〉 "내일 일정 알려줘" 〈출력 나오면〉 "모델이 이 함수를 골라 부르고, 반환값으로 답을 만들었습니다. 이 왕복은 제가 짠 게 아니라 기본 전략이 합니다. 참고로 캘린더는 발표용 가짜입니다. 진짜 연동이면 return 안쪽만 바꾸면 되고, 바깥은 그대로입니다."

## 9. 3/5 스킬 (50초)

"이번엔 능력을 파일로 꽂습니다."

〈frontmatter 위부터〉 "스킬은 frontmatter 달린 마크다운 파일 하나입니다. 이 description 한 줄들의 목록이 에이전트가 들고 있는 스킬 카탈로그가 됩니다. '판교 사투리라고 말하면 이 스킬을 쓴다'까지 적혀 있습니다."

〈본문 강도〉 "본문에는 강도 1부터 11까지 지침이 있는데, 요청이 스킬에 해당할 때만 에이전트가 파일을 읽어 따릅니다. 프롬프트에 미리 싣지 않으니 토큰도 아낍니다."

"여기서 Koog가 해 주는 건 둘입니다. 폴더에서 SKILL.md를 찾아 주고, 그 설명 목록을 프롬프트 문자열로 만들어 줍니다. 제가 한 건 에이전트에 파일 읽기 도구를 쥐여 준 것뿐입니다."

〈터미널 2〉 "판교 사투리 3으로 바꿔 줘: 내일 회식 오세요" 〈출력〉 "강도 3, 부드러운 사내 메모입니다."

〈여유 있으면〉 "끝까지 올리면 이렇게 됩니다." → "판교 사투리 11로 바꿔 줘: 내일 회식 오세요"

## 10. 4/5 라우팅 (50초)

"여기서 문제가 하나 생깁니다. 도구와 스킬을 한 에이전트에 다 주면, 이 4B 로컬 모델은 프롬프트로 아무리 일러도 엉뚱한 도구를 짚습니다. 요청을 갈라야 합니다."

〈강조된 edge 두 줄〉 "Koog에서 분기는 if문이 아니라 엣지 선언입니다. 일정이라는 말이 들어 있으면 2단계의 그 캘린더를 읽고, 그 결과가 reply 노드로 흘러 들어가 비서 말투로 나옵니다. 나머지 질문은 바로 reply로 갑니다. 조회 결과가 다음 노드의 입력으로 흐르는 것, 이게 노드 연결입니다."

〈아래 실행 결과〉 "일정 질문은 캘린더가, 점심 질문은 모델이 받습니다."

〈오른쪽 규칙〉 "규칙은 하나만 기억하시면 됩니다. 엣지는 선언한 순서대로 검사됩니다. 그래서 모두 받는 true 엣지는 반드시 마지막입니다."

"하나는 정직하게 말씀드립니다. 분기를 빠뜨려도 컴파일러는 모릅니다. when과 다른 점입니다."

"그리고 이 edge 줄은 실행문이 아니라 그래프라는 자료구조를 만듭니다. 값이니까 실행 전에 만질 수 있습니다. 그 덕을 다음 장에서 봅니다."

## 11. 5/5 시각화 (30초)

〈다이어그램〉 "방금 그 라우팅 전략에 asMermaidDiagram()을 한 번 부른 출력입니다. 따로 그린 그림이 아니라 코드에서 나온 그림이라, 코드가 바뀌면 그림도 바뀝니다."

〈강조 박스〉 "분기 선언도, 타입 검사도, 이 그림도 전부 전략이 자료구조라서 얻는 겁니다. 이게 Koog 설계의 핵심입니다."

## 예상 질문

- **진짜 캘린더면?** "@Tool 자리를 MCP 도구 레지스트리로 바꾸면 됩니다. Koog가 MCP 서버의 도구를 같은 ToolRegistry로 가져옵니다." (기능 범위의 MCP 칩)
- **LangChain4j와 차이는?** "그래프를 1급 자료구조로 두느냐가 갈림길입니다. 직접 비교한 89분 영상이 소개 장 출처에 있습니다."
- **모델을 바꾸면?** "application.properties의 spring.ai 설정만 바꾸면 됩니다. 브리지가 ChatModel을 감싸는 구조라서요."
- **분기 누락은 어떻게 막나?** "true 받침 엣지를 관례로 두는 수밖에 없습니다. when 같은 전수 검사는 없습니다."
- **calls 리스트는 뭔가?** "모델의 도구 호출을 검증하는 테스트용 기록입니다. LLM 응답은 흔들려도 도구 호출 여부는 단정할 수 있어서요."
- **tool과 tools 차이는?** "tools는 @Tool 함수를 품은 클래스를 통째로 스캔하고, tool은 완성된 Tool 객체 하나를 넣습니다."

## 준비 체크리스트

- 모델 웜업 + 2시간 고정 (발표 직전 1회):
  `curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null`
- 터미널 두 개를 미리 띄워 웜업 질문 한 번씩: 터미널 1 `koog step1`, 터미널 2 `koog`
  (명령 설치 위치는 /opt/homebrew/bin/koog. 내부에서 bootJar 후 jar 실행)
- 데모 입력을 복사해 둘 것 (2 더하기 3 / 내일 일정 / 판교 사투리 3 / 판교 사투리 11 / 첫 번째 일정)
- 슬라이드는 file://로 열고 #1 확인 (키보드 →로 진행)
