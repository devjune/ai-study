# 데모 시나리오

터미널에서 손이 할 일만 적는다. 할 말은 `발표 스크립트.md`에 있다. 출력은 전부 실제로 돌려 받은 것(Koog 1.3.0, qwen3:4b-instruct, temperature 0). 모델 출력이라 글자 단위로는 달라질 수 있고, 아래 "어긋날 때"에 대처를 적었다.

## 실행 명령

| 명령 | 프로필 | 코드 | 쓰는 장 |
|---|---|---|---|
| `koog step1` | step1 | Harness07.kt: AIAgent 하나와 readLine 루프 | 7장 |
| `koog` | harness | Harness12.kt: dispatchRouter + 비서(캘린더, 챗 메모리, 체크포인트, 검증 전략) + 스킬 에이전트, 전부에 이벤트 트레이스 | 8~13장, 15장 |

`koog`는 /opt/homebrew/bin/koog. 안에서 `./gradlew bootJar` 뒤 `java -jar … --spring.profiles.active=<프로필>`을 실행한다. 기동은 약 10초, `❯` 프롬프트가 뜨면 준비된 것이다. 종료는 `exit` 또는 Ctrl-D.

터미널 2(harness)는 JLine이라 ↑로 이전 입력을 다시 쓸 수 있다. 터미널 1(step1)은 readLine이라 ↑가 안 된다.

## 준비 (발표 10분 전)

1. Ollama 확인과 모델 웜업. 2시간 동안 메모리에 고정된다.
   ```bash
   curl -s localhost:11434/api/tags | grep -o qwen3:4b-instruct
   curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null
   ```
2. 체크포인트 폴더와 캘린더 파일을 비운다. 리허설에서 죽인 실행이 남아 있으면 기동하자마자 자동 재개되고, 리허설에서 추가한 일정이 남아 있으면 기본 두 건이 아니다.
   ```bash
   rm -rf /tmp/koog-checkpoints /tmp/koog-calendar.txt
   ```
3. 터미널 1에서 `koog step1`. `❯`가 뜨면 `안녕` 한 번 쳐서 JVM을 데운다. 답은 무시. 7장 뒤에는 `exit`로 나와서 12장용 명령을 쳐 둔다(Enter는 누르지 않는다).
   ```bash
   pkill -9 -f 'profiles.active=harness'
   ```
4. 터미널 2에서 `koog`. `❯`가 뜨면 `판교 사투리 1로 바꿔 줘: 안녕하세요` 한 번. 스킬 에이전트로 가서 파일 읽기까지 데워지고, 비서 세션(demo) 이력에는 남지 않는다. 비서 쪽 질문으로 데우면 11장 이력에 섞이니 피한다.
5. 슬라이드를 file://로 열고 #1 확인. 터미널 글꼴은 슬라이드 코드와 비슷한 크기로.
6. 아래 입력 문장을 복사해 둔다. 띄어쓰기까지 그대로.

## 흐린 줄 읽는 법

답 위에 흐리게 찍히는 줄은 데모 코드가 Koog EventHandler로 남기는 실행 흐름이다(Trace.kt). 8장부터 11장까지 실제 화면:

```
❯ 내일 일정 알려줘
  dispatch    → assistant
  assistant   LLM #1 메시지 2개 → 도구 호출 schedules(day=내일)  1.0s
  assistant   schedules → 10:00 팀 싱크, 14:00 디자인 리뷰
  assistant   LLM #2 메시지 4개 → 답  1.1s
  assistant   완료 2.1s
내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.
❯ 판교 사투리 3으로 바꿔 줘: 내일 회식 오세요
  dispatch    → skill
  skill       LLM #1 메시지 2개 → 도구 호출 __read_file__(path=…/pangyo-dialect/SKILL.md)  1.3s
  skill       __read_file__ → 2,047자
  skill       LLM #2 메시지 4개 → 답  4.9s
  skill       완료 6.2s
내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.
❯ 아까 말한 첫 번째 일정이 뭐였지?
  dispatch    → assistant
  assistant   LLM #1 메시지 4개 (이력 2개) → 답  0.6s
  assistant   완료 0.6s
10:00 팀 싱크입니다.
```

- `dispatch → …`: 라우터 전략이 들어간 노드. 판교 사투리는 skill, 나머지는 assistant (10장).
- `LLM #n 메시지 N개 → 결정  시간`: 모델 호출 하나. 결정은 "도구 호출 이름(인자)" 아니면 "답". 도구 왕복이면 #1이 도구 호출, #2가 답(8장). 첫 호출의 "(이력 M개)"는 챗 메모리가 실어 준 앞 대화 수(11장).
- `도구이름 → 결과`: 도구가 돌려준 값. 파일은 글자 수.
- `완료 시간`: 담당 에이전트의 실행 전체. 스킬은 파일 읽기와 긴 답 때문에 가장 오래 걸린다.
- `persistence 중단된 실행 발견, … 다음부터 이어감`: 기동 때 완료 표시 없는 체크포인트를 찾았다는 뜻(12장).
- `검증: … 겹침 (…) → 도구 실행 전 체크포인트로 롤백`과 `롤백 뒤 내일 일정: …`: 전략의 verify 노드와 reject 노드가 찍는 줄(13장). 사이에 remove 줄은 없다. 반대 도구는 이벤트에 안 잡힌다.
- 시간은 실행마다 조금씩 다르다. 터미널 1(`koog step1`)에는 이 줄이 없다. 7장과의 대비가 그 자체로 설명이다.

## 12·13장 절차: 퍼시스턴스 (중단 뒤 이어서, 롤백과 반대 도구)

두 절차가 같은 체크포인트를 쓰지만 하는 일이 다르다. 12장은 프로세스를 밖에서 죽이고 다시 띄워 **이어서** 하는 것이고, 13장은 프로세스가 산 채로 같은 실행 안에서 앞 체크포인트로 **되돌리는** 것이다.

전제: 터미널 2에 `koog`가 떠 있고 11장까지 진행한 상태. 터미널 1에는 `pkill -9 -f 'profiles.active=harness'`가 쳐져 있고 Enter만 남아 있다.

### 왜 이렇게 하나

- 왜 죽이나: 퍼시스턴스가 내세우는 것이 장애 복구라서 장애를 일부러 만든다. 정상 종료는 완료 표시가 남아 재개할 것이 없다. 실행이 도중에 끊겨야 "완료 표시 없는 체크포인트"가 생기고, 재시작 때 앞서 한 모델 호출과 도구 호출을 건너뛰는 장면이 나온다. 실무의 배포 재시작, OOM, 서버 장애를 kill로 대신한다.
- 왜 `-9`인가: Ctrl-C는 JVM이 정리 종료를 하는 동안 진행 중이던 모델 호출이 끝나 버려 정상 완료로 기록된다. 즉시 죽여야 끊긴 상태가 남는다.
- 왜 긴 질문인가: 도구 호출 뒤 둘째 모델 호출이 몇 초 걸리는 틈에 죽여야 도구 결과까지는 체크포인트에 있고 답만 없는 상태가 된다. 짧은 질문은 틈이 없다.
- 왜 14시인가: 기본 일정에 14:00 디자인 리뷰가 있어 겹친다. 10시(팀 싱크)도 겹치고, 16시는 안 겹친다. 한 번 추가한 시각은 파일에 남으니 재시작 뒤 같은 시각을 다시 넣어도 겹쳐서 롤백된다.

### 설명할 때 받을 질문

- 중단과 롤백이 뭐가 다른가: 중단은 프로세스가 죽고 다음 기동이 이어받는 것. 롤백은 프로세스가 산 채로 같은 실행 안에서 앞 체크포인트로 돌아가는 것. 둘 다 노드 뒤마다 남는 같은 체크포인트를 쓴다.
- remove가 왜 트레이스에 없나: Persistence가 도구 객체를 직접 실행해서 EventHandler의 도구 이벤트에 안 잡힌다. 롤백 뒤 목록에서 치과가 빠진 것으로 확인한다.
- 왜 receive 노드가 있나: 자동 체크포인트는 시작 노드에는 안 남는다. "도구 실행 전" 체크포인트를 가지려면 요청을 받기만 하는 노드가 앞에 있어야 한다.
- 되돌리기가 왜 verify 안에서 바로 안 보이나: rollbackToCheckpoint는 복원 데이터를 넣어 두고, 노드가 끝난 뒤 전략 실행기가 반대 도구, 실행 지점, 프롬프트 순으로 적용한다. 그래서 "롤백 뒤 목록"은 reject 노드에서 찍는다.
- 거절한 턴이 왜 이력에 없나: receive 뒤 체크포인트에는 이 턴의 질문이 아직 없고(질문은 모델 호출 노드가 프롬프트에 붙임), 롤백이 프롬프트를 그 상태로 돌려놓은 채 모델 호출 없이 끝나기 때문이다.

### 어긋날 때

- 틈을 놓쳐 답이 끝난 뒤 죽임: 재시작해도 재개할 게 없다(완료 표시가 있음). 같은 입력으로 한 번 더 한다. 두 번 놓치면 슬라이드의 출력 블록으로 설명한다. 같은 캡처다.
- Ctrl-C로 끊음: 정상 완료로 기록돼 재개가 안 된다. 터미널 1의 `pkill -9`로 다시 한다.
- 기동하자마자 `중단된 실행 발견`이 찍힘: 리허설에서 죽인 실행이 남은 것. 그대로 두면 답을 마저 내고 끝나고, 깔끔히 하려면 `exit` 뒤 `rm -rf /tmp/koog-checkpoints`, 다시 `koog`.
- 8장에서 기본 두 건 말고 다른 일정이 보임: 리허설에서 추가한 일정이 /tmp/koog-calendar.txt에 남은 것. `exit` 뒤 `rm -f /tmp/koog-calendar.txt`, 다시 `koog`.
- 13장에서 롤백이 안 찍히고 그냥 추가됨: 모델이 add 인자를 14:00이 아닌 값으로 넘긴 것. 트레이스의 `add(…)` 인자를 확인하고 ↑로 같은 입력을 다시 친다. temperature 0이라 실측에서는 항상 14:00이었다.

## 15장 즉흥 입력 후보 (실측 통과)

| 입력 | 출력 | 보여주는 것 |
|---|---|---|
| `두 번째 일정은 몇 시였지?` | `14:00 디자인 리뷰입니다.` | 이력에서 답함 |
| `내 이름은 준이야` 뒤에 `내 이름이 뭐지?` | `안녕하세요, 준이님. 어떻게 도와드릴까요?` 뒤에 `당신의 이름은 준이에요.` | 도구 없이 기억만으로 답함 |
| `내일 16시에 치과 추가해 줘` 뒤에 `내일 일정 알려줘` | `내일 16:00 치과 일정이 추가되었습니다.` 뒤에 `10:00 팀 싱크, 14:00 디자인 리뷰, 16:00 치과` 목록 | 부작용 있는 도구. 트레이스에 `add(day=내일, time=16:00, title=치과)`, 겹치지 않아 롤백 없음 |
| `내일 10시에 운동 추가해 줘` | `내일 10:00은 이미 팀 싱크 시간이라 운동 일정을 추가하지 않았습니다.` | 13장과 같은 롤백(팀 싱크와 겹침). 트레이스에 `add(day=내일, time=10:00, title=운동)` 뒤 검증·롤백 줄 |
| `판교 사투리 7로 바꿔 줘: 점심 같이 먹어요` | `점심 같이 먹고자 합니다. 싱크해 주세요.` | 스킬 강도 중간 |
| `모레 일정은?` | `모레는 일정이 없습니다.` 류 | 없는 날은 없다고 답함 |
| `내일 일정 알려줘` 뒤에 `판교 사투리 7로 일정 공지 만들어 줘` | `오늘은 10:00 팀 싱크, 14:00 디자인 리뷰를 진행하고자 합니다. … 린하게 팔로업 …` | 비서 답변을 스킬이 이어받음. 11은 예시 문구가 섞일 수 있음 |
| `오늘 점심 뭐 먹을까?` | `점심은 카페에서 커피와 토스트를 먹는 걸 추천해요!` | 일정 아닌 질문은 도구 없이 비서가 답함 |
| `판교사투리란?` | SKILL.md를 읽고 강도 1~11 설명을 요약해 답함 | 스킬 요청은 띄어쓰기와 무관하게 스킬 에이전트로. 질문도 파일을 읽고 답함 |

청중에게 미리 말해 둘 규칙 둘. "판교 사투리"가 들어간 문장은 스킬 에이전트로 간다. 스킬 에이전트는 대화 이력이 없고, 대신 직전 비서 답변이 "바꿀 원문"으로 붙어 넘어간다. 그래서 "내일 일정 알려줘" 뒤에 "판교 사투리 7로 일정 공지 만들어 줘"가 된다. 콜론이 있으면 콜론 뒤 문장을 바꾸고, 없으면 직전 답변을 바꾼다. 강도는 꼭 적고, 공지는 7을 권한다. 11은 SKILL.md의 예시 문구가 섞여 없는 사실(야근, 순연)이 붙을 때가 있다. 안 적으면 원문을 그대로 돌려준다. 나머지 문장은 비서로 가고 기억이 있으며, 일정 질문이면 캘린더 도구를 부른다. 캘린더는 발표용 가짜다. 기본 일정은 "내일"에만 두 건 있고 다른 날짜는 "없음"을 돌려준다. add로 추가한 일정은 그 날짜 문자열(예: "모레")에 붙는다. 일정은 /tmp/koog-calendar.txt에 저장돼 재시작해도 남는다. 체크포인트가 남기는 것은 실행 상태이고 일정 데이터는 캘린더 쪽 저장소의 몫이라는 구분이 여기서 보인다.

실측(강도 7, 직전 답변이 내일 일정일 때):

```
❯ 판교 사투리 7로 일정 공지 만들어 줘
  dispatch    → skill
  skill       LLM #1 메시지 2개 → 도구 호출 __read_file__(path=…/pangyo-dialect/SKILL.md)
  skill       __read_file__ → 2,047자
  skill       LLM #2 메시지 4개 → 답
내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.
내일 10:00 팀 싱크, 14:00 디자인 리뷰가 진행 예정이니, 각자 액션 아이템을 린하게 팔로업하고, 참석 여부는 지라에 티켓으로 끊어 주세요. 홀드된 사항은 컨플에 업데이트 후, 다음 회고에서 레슨런으로 공유 부탁드립니다.
```

4B 모델이라 긴 문장, 영어 섞인 문장, 여러 요청을 한 줄에 넣은 문장은 흔들린다. 한 줄에 한 가지만 받는다.

## 어긋날 때

- `❯`가 안 뜸: Ollama가 꺼졌거나 모델이 없다. 준비 1번을 다시 한다.
- 기동하자마자 `persistence 중단된 실행 발견`이 찍힘: 리허설에서 죽인 실행이 남은 것. 그대로 두면 답을 마저 내고 끝나니 무시해도 되고, 깔끔히 하려면 `exit` 뒤 `rm -rf /tmp/koog-checkpoints`, 다시 `koog`.
- 스킬 요청이 비서로 감: 입력에 "판교사투리"가 들어 있어야 한다(띄어쓰기는 무관). "판교 말투"처럼 다른 말은 비서로 간다.
- "뭐 할 수 있어?"에 비서가 스킬을 모른다고 답함: 설계상 그렇다. 스킬 이름을 대라고 안내한다("판교사투리란?"). 비서 프롬프트에 카탈로그를 넣으면 말투가 흔들려 뺐다.
- 콜론 규칙: 스킬 요청에 콜론(:)이 있으면 그 뒤 문장을 바꾸고, 없으면 직전 비서 답변을 바꾼다. "판교 사투리 7로 일정 공지 만들어 줘"는 후자.
- 스킬 에이전트가 파일을 못 읽음: 스킬 폴더는 기동 때마다 /tmp/koog-skills로 복사된다. `exit` 후 `koog`를 다시 띄운다.
- 비서가 일정을 지어냄: 이력이 있을 때 4B가 도구를 안 부르고 이력으로 답하는 일이 있다. 프롬프트에 "'모레 일정은?' → schedules(day=모레)" 예시를 넣은 뒤로 이력 두어 개까지는 도구를 부르지만, 네댓 개 넘게 쌓이면 다시 건너뛸 수 있다. 다른 날짜 질문은 세션 초반에 하고, 틀리면 `exit` 뒤 `koog`로 이력을 비운다.
- 대화가 꼬임: `exit` 후 `koog`. 대화 이력은 메모리에만 있어 재시작하면 비워진다. 11장 전이라면 8장 입력부터 다시.
- 7장 터미널 1이 느림: 첫 요청은 JVM 워밍업이 섞인다. 준비 3번을 건너뛰었을 때 생긴다.
