# 데모 시나리오

입력과 예상 답을 순서대로 적는다. 할 말은 `발표 스크립트.md`. 답은 실측(Koog 1.3.0, qwen3:4b-instruct, temperature 0)이고 글자 단위로는 달라질 수 있다.

## 준비 (발표 10분 전)

1. 모델 웜업(2시간 고정):
   ```bash
   curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null
   ```
2. 지난 실행 상태 비우기:
   ```bash
   rm -rf demo-phase3/data
   ```
3. IntelliJ 실행 구성 둘. 메인 클래스 Phase3Application, 작업 디렉터리 `demo-phase3`, 프로그램 인자 `--spring.profiles.active=step1` / `--spring.profiles.active=harness`. 둘 다 띄워 `❯`가 뜨는지 본다.
4. step1에 `안녕` 한 번, harness에 `판교 사투리 1로 바꿔 줘: 안녕하세요` 한 번(웜업).

## 순서

### 1. 기본 에이전트 (슬라이드 7, step1)

입력: `2 더하기 3은?`
답: `5`

### 2. 도구 (슬라이드 8, 여기부터 끝까지 harness)

입력: `내일 일정 알려줘`
답: `내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.`
보는 것: 답 위의 `schedules(day=내일)` 줄과 `schedules → …` 줄. 모델이 도구를 골라 부르고 그 결과로 답했다.

### 3. 스킬 (슬라이드 9)

입력: `판교 사투리 3으로 바꿔 줘: 내일 회식 오세요`
답: `내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.`
보는 것: `dispatch → skill`, `__read_file__(…SKILL.md)`. 파일을 읽은 뒤 답했다. 10초 안쪽이면 정상.

### 4. 오케스트레이션 (슬라이드 10)

입력 없음. 2번의 `dispatch → assistant`와 3번의 `dispatch → skill`을 가리킨다.

### 5. 챗 메모리 (슬라이드 11)

입력: `아까 말한 첫 번째 일정이 뭐였지?`
답: `10:00 팀 싱크입니다.`
보는 것: `LLM #1 메시지 4개 (이력 2개)`. 도구 줄 없이 이력으로 답했다.

### 6. 퍼시스턴스, 중단 뒤 이어서 (슬라이드 12)

기본은 슬라이드의 출력 블록으로 설명한다. 라이브로 할 때:

입력: `내일 일정 알려 주고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘`
`schedules → …` 줄이 보이면 Terminal 탭에서 `pkill -9 -f Phase3Application` (Stop 버튼은 정상 종료라 안 됨)
같은 구성을 다시 실행.
답: 첫 줄 `persistence 중단된 실행 발견, verify 다음부터 이어감`, 이어서 긴 답.
보는 것: 도구 줄 없이 `LLM #1` 하나. 앞서 한 모델 호출과 도구 호출을 다시 하지 않았다.
놓쳤으면: 답이 끝난 뒤 죽인 것이라 재개할 게 없다. 같은 입력으로 다시.

### 7. 퍼시스턴스, 롤백 (슬라이드 13)

입력: `내일 14시에 치과 추가해 줘`
답: `내일 14:00은 이미 디자인 리뷰 시간이라 치과 일정을 추가하지 않았습니다.`
보는 것:
- `add → 추가됨: 내일 14:00 치과`: 도구가 실제로 돌았다.
- `검증: 14:00 치과 겹침 (14:00 디자인 리뷰) → 도구 실행 전 체크포인트로 롤백`
- `롤백 뒤 내일 일정: 10:00 팀 싱크, 14:00 디자인 리뷰`: 치과가 빠졌다. remove는 코드에 없고 Koog가 불렀다. 트레이스에는 안 찍힌다.
- 모델 호출은 한 번. 다음 턴의 "(이력 N개)"가 그대로라 이 턴은 이력에 안 남았다.

### 8. 즉흥 입력 (슬라이드 15)

| 입력 | 답 |
|---|---|
| `두 번째 일정은 몇 시였지?` | `14:00 디자인 리뷰입니다.` |
| `내일 16시에 치과 추가해 줘` | `내일 16:00 치과 일정이 추가되었습니다.` (겹치지 않아 롤백 없음) |
| `내일 일정 알려줘` | `10:00 팀 싱크, 14:00 디자인 리뷰, 16:00 치과` 목록 |
| `내일 10시에 운동 추가해 줘` | `내일 10:00은 이미 팀 싱크 시간이라 운동 일정을 추가하지 않았습니다.` |
| `모레 일정은?` | `모레는 일정이 없습니다.` 류 |
| `내 이름은 준이야` 뒤에 `내 이름이 뭐지?` | `당신의 이름은 준이에요.` |
| `판교 사투리 7로 바꿔 줘: 점심 같이 먹어요` | `점심 같이 먹고자 합니다. 싱크해 주세요.` |
| `판교 사투리 7로 일정 공지 만들어 줘` (일정 답 직후) | 직전 답을 공지로 바꿈 |
| `오늘 점심 뭐 먹을까?` | 도구 없이 비서가 답함 |
| `판교사투리란?` | SKILL.md를 읽고 강도 1~11 요약 |

청중에게 미리 말할 규칙: "판교 사투리"가 들어가면 스킬 에이전트로 간다. 콜론이 있으면 콜론 뒤를, 없으면 직전 비서 답변을 바꾼다. 강도는 꼭 적고 공지는 7. 캘린더는 가짜라 "내일"에만 두 건 있다. 한 줄에 한 가지만.

## 질문 대비: 체크포인트가 있을 때와 없을 때 (실측)

"메시지를 DB에 두면 되는 것 아닌가"에 답하는 비교. 코드 변경 없이 된다.

A. 있을 때
입력: `내일 16시에 치과 추가하고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘`
`add → 추가됨: 내일 16:00 치과` 줄이 보이면 `pkill -9`, 다시 실행.
답: `중단된 실행 발견, verify 다음부터 이어감` 뒤 `LLM #1 → 답`. add는 한 번만 돌았다. `cat data/koog-calendar.txt`에 16:00 치과 한 건.

B. 없을 때
입력: `내일 17시에 미용실 추가하고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘`
`add → 추가됨` 줄이 보이면 `pkill -9`, 그리고 `rm -rf demo-phase3/data/koog-checkpoints`, 다시 실행.
답: 재개 줄이 없다. 같은 입력을 다시 넣으면 `add → 추가됨: 내일 17:00 미용실`이 또 찍힌다(두 번째 실행). 이어서 `검증: 17:00 미용실 겹침 (17:00 미용실) → 롤백`.
보는 것: 메시지만 남기면 요청을 처음부터 다시 돌려야 하고 부작용 있는 도구가 다시 돈다. 여기서는 검증 노드가 중복을 잡았을 뿐이다.

한 줄: 저장 위치(파일, DB)는 바꿔 끼우는 것이고, 차이는 저장 내용(어느 노드까지 끝났는지와 그 출력), 저장 시점(노드마다 자동), 이어받는 주체(같은 runId로 run하면 Koog)다.

## 실행 기록 줄

- `dispatch → …`: 라우터가 보낸 곳. skill 또는 assistant
- `LLM #n 메시지 N개 → 결정  시간`: 모델 호출 하나. 결정은 "도구 호출 이름(인자)" 아니면 "답". "(이력 M개)"는 챗 메모리가 실어 준 앞 대화 수
- `도구이름 → 결과`: 도구가 돌려준 값
- `검증: …`, `롤백 뒤 …`: 비서 전략의 verify, reject 노드가 찍는 줄
- `persistence 중단된 실행 발견 …`: 기동 때 완료 표시 없는 체크포인트를 찾음

## 어긋날 때

- `❯`가 안 뜸: Ollama나 모델 확인. 준비 1번부터.
- 기동하자마자 `중단된 실행 발견`이 찍히거나 2번 답이 두 건이 아님: 지난 `data/`가 남은 것. 종료 뒤 `rm -rf demo-phase3/data`, 다시.
- 스킬 요청이 비서로 감: "판교사투리"가 들어 있어야 한다(띄어쓰기 무관).
- 비서가 일정을 지어냄: 이력이 네댓 개 넘으면 4B가 도구를 건너뛸 수 있다. 재시작해 이력을 비우고 2번부터.
- 같은 추가 요청을 두 번째 넣었는데 도구 줄 없이 "추가됨"만 답함: 이력의 앞 답을 되풀이한 것. 다른 제목이나 시각으로.
- 7번에서 롤백이 안 찍히고 그냥 추가됨: add 인자가 14:00이 아님. ↑로 같은 입력을 다시.
