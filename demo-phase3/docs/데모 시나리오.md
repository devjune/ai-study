# 데모 시나리오

손이 할 일만 적는다. 할 말은 `발표 스크립트.md`에 있다. 출력은 전부 실제로 돌려 받은 것(Koog 1.3.0, qwen3:4b-instruct, temperature 0)이고, 모델 출력이라 글자 단위로는 달라질 수 있다.

## 실행

IntelliJ 실행 구성 둘. 메인 클래스는 둘 다 Phase3Application, 작업 디렉터리는 `demo-phase3`.

| 구성 | 프로그램 인자 | 쓰는 장 |
|---|---|---|
| step1 | `--spring.profiles.active=step1` | 7장 |
| harness | `--spring.profiles.active=harness` | 8~13장, 15장 |

터미널로 하려면 `koog step1`, `koog`(/opt/homebrew/bin/koog, bootJar 뒤 jar 실행). 어느 쪽이든 `❯`가 뜨면 준비된 것이다. 종료는 `exit`.

## 준비 (발표 10분 전)

1. 모델 웜업. 2시간 동안 메모리에 고정된다.
   ```bash
   curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null
   ```
2. 지난 실행 상태 비우기. 체크포인트와 캘린더 파일이 여기 남는다. 안 비우면 기동 때 자동 재개되거나 8장 일정이 기본 두 건이 아니다.
   ```bash
   rm -rf demo-phase3/data
   ```
3. step1 구성을 띄워 `안녕` 한 번(JVM 웜업). harness 구성을 띄워 `판교 사투리 1로 바꿔 줘: 안녕하세요` 한 번(스킬 에이전트 웜업, 비서 이력에는 안 남음).
4. 슬라이드 #1 확인. 아래 입력을 복사해 둔다.

## 진행

| 장 | 구성 | 입력 | 답(실측) |
|---|---|---|---|
| 7 | step1 | `2 더하기 3은?` | `5` |
| 8 | harness | `내일 일정 알려줘` | `내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.` |
| 9 | harness | `판교 사투리 3으로 바꿔 줘: 내일 회식 오세요` | `내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.` |
| 10 | 입력 없음 | 8장은 assistant로, 9장은 skill로 간 `dispatch` 줄을 가리킨다 | |
| 11 | harness | `아까 말한 첫 번째 일정이 뭐였지?` | `10:00 팀 싱크입니다.` |
| 12 | 입력 없음 | 슬라이드의 출력 블록(실측 캡처)으로 설명한다. 라이브는 아래 "중단 데모" | |
| 13 | harness | `내일 14시에 치과 추가해 줘` | `내일 14:00은 이미 디자인 리뷰 시간이라 치과 일정을 추가하지 않았습니다.` |
| 15 | harness | 청중 즉흥 입력 | 아래 후보 |

harness는 8장부터 끝까지 한 세션이다. 11장의 답은 8장의 답을 이력에서 꺼낸 것이라, 중간에 재시작하면 8장 입력을 먼저 다시 친다.

## 실행 기록 줄 읽는 법

답 위에 찍히는 줄은 EventHandler로 남기는 실행 기록이다.

- `dispatch → …`: 라우터 전략의 노드. 판교 사투리는 skill, 나머지는 assistant
- `LLM #n 메시지 N개 → 결정  시간`: 모델 호출 하나. 결정은 "도구 호출 이름(인자)" 아니면 "답". "(이력 M개)"는 챗 메모리가 실어 준 앞 대화 수
- `도구이름 → 결과`: 도구가 돌려준 값
- `완료 시간`: 담당 에이전트의 실행 전체
- `검증: …`, `롤백 뒤 …`: 비서 전략의 verify 노드와 reject 노드가 찍는 줄(13장)
- `persistence 중단된 실행 발견, … 다음부터 이어감`: 기동 때 완료 표시 없는 체크포인트를 찾았다는 뜻(12장)

## 13장 롤백에서 짚을 것

```
❯ 내일 14시에 치과 추가해 줘
  dispatch    → assistant
  assistant   LLM #1 메시지 8개 (이력 6개) → 도구 호출 add(day=내일, time=14:00, title=치과)  2.4s
  assistant   add → 추가됨: 내일 14:00 치과
  assistant   검증: 14:00 치과 겹침 (14:00 디자인 리뷰) → 도구 실행 전 체크포인트로 롤백
  assistant   롤백 뒤 내일 일정: 10:00 팀 싱크, 14:00 디자인 리뷰
  assistant   완료 2.4s
내일 14:00은 이미 디자인 리뷰 시간이라 치과 일정을 추가하지 않았습니다.
```

- `add → 추가됨`: 도구가 실제로 돌았다.
- `검증 … 롤백`: verify 노드가 receive 뒤 체크포인트(도구 실행 전)로 되돌렸다.
- `롤백 뒤 내일 일정`에 치과가 없다: remove는 코드에 없고 Koog가 불렀다(RollbackToolRegistry). 트레이스에는 안 찍힌다.
- 모델 호출은 한 번이다. 거절한 턴은 이력에 안 남는다(다음 턴의 "(이력 N개)"가 그대로).
- 일정은 `data/koog-calendar.txt`에 남는다. 재시작 뒤 같은 시각을 또 넣어도 롤백된다. 체크포인트는 실행 상태, 일정은 캘린더 저장소의 몫이다.

## 중단 데모 (라이브로 할 때만)

1. harness에 `내일 일정 알려 주고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘`. 답이 길어 둘째 모델 호출이 몇 초 걸린다. 그 사이가 죽일 틈이다.
2. `schedules → …` 줄이 찍히면 IntelliJ Terminal 탭에서 `pkill -9 -f Phase3Application`. Run 창의 Stop 버튼은 정상 종료를 먼저 시도해서 그 사이 모델 호출이 끝나 버릴 수 있다. 콘솔이 exit code 137로 끝난다.
3. 같은 구성을 다시 실행. `❯` 전에 `persistence 중단된 실행 발견, verify 다음부터 이어감`이 찍히고 모델 호출 한 번으로 답이 이어진다. 도구는 다시 부르지 않는다.

틈을 놓쳐 답이 끝난 뒤 죽였으면 재개할 게 없다(완료 표시가 있음). 같은 입력으로 한 번 더 한다.

## 15장 즉흥 입력 후보 (실측 통과)

| 입력 | 출력 | 보여주는 것 |
|---|---|---|
| `두 번째 일정은 몇 시였지?` | `14:00 디자인 리뷰입니다.` | 이력에서 답함 |
| `내 이름은 준이야` 뒤에 `내 이름이 뭐지?` | `안녕하세요, 준이님. 어떻게 도와드릴까요?` 뒤에 `당신의 이름은 준이에요.` | 도구 없이 기억만으로 답함 |
| `내일 16시에 치과 추가해 줘` 뒤에 `내일 일정 알려줘` | `내일 16:00 치과 일정이 추가되었습니다.` 뒤에 `10:00 팀 싱크, 14:00 디자인 리뷰, 16:00 치과` 목록 | 겹치지 않는 추가. 롤백 없음 |
| `내일 10시에 운동 추가해 줘` | `내일 10:00은 이미 팀 싱크 시간이라 운동 일정을 추가하지 않았습니다.` | 13장과 같은 롤백 |
| `판교 사투리 7로 바꿔 줘: 점심 같이 먹어요` | `점심 같이 먹고자 합니다. 싱크해 주세요.` | 스킬 강도 중간 |
| `모레 일정은?` | `모레는 일정이 없습니다.` 류 | 없는 날은 없다고 답함 |
| `내일 일정 알려줘` 뒤에 `판교 사투리 7로 일정 공지 만들어 줘` | `… 린하게 팔로업 …` 공지 | 비서 답변을 스킬이 이어받음 |
| `오늘 점심 뭐 먹을까?` | `점심은 카페에서 커피와 토스트를 먹는 걸 추천해요!` | 일정 아닌 질문은 도구 없이 답함 |
| `판교사투리란?` | SKILL.md를 읽고 강도 1~11을 요약 | 띄어쓰기와 무관하게 스킬 에이전트로 |

청중에게 미리 말할 규칙: "판교 사투리"가 들어간 문장은 스킬 에이전트로 간다. 콜론이 있으면 콜론 뒤 문장을, 없으면 직전 비서 답변을 바꾼다. 강도는 꼭 적고 공지는 7을 권한다(11은 예시 문구가 섞일 수 있음). 나머지는 비서로 가고 기억이 있다. 캘린더는 가짜라 기본 일정은 "내일"에만 두 건이고 다른 날짜는 "없음"이다. 4B 모델이라 한 줄에 한 가지만 받는다.

## 어긋날 때

- `❯`가 안 뜸: Ollama가 꺼졌거나 모델이 없다. 준비 1번부터 다시.
- 기동하자마자 `중단된 실행 발견`이 찍히거나 8장 일정이 기본 두 건이 아님: 지난 실행의 `data/`가 남은 것. `exit` 뒤 `rm -rf demo-phase3/data`, 다시 실행.
- 스킬 요청이 비서로 감: 입력에 "판교사투리"가 들어 있어야 한다(띄어쓰기 무관).
- "뭐 할 수 있어?"에 비서가 스킬을 모른다고 답함: 설계상 그렇다. 스킬 이름을 대라고 안내한다.
- 비서가 일정을 지어냄: 이력이 네댓 개 넘게 쌓이면 4B가 도구를 건너뛸 수 있다. 재시작해 이력을 비우고 8장부터 다시.
- 같은 추가 요청을 두 번째 넣었는데 도구 줄 없이 "추가됨"만 답함: 이력에 앞의 "추가됨" 답이 있으면 4B가 add를 안 부르고 되풀이할 수 있다. 실측 1회. 다른 제목이나 시각으로 넣는다.
- 13장에서 롤백이 안 찍히고 그냥 추가됨: 모델이 add 인자를 14:00이 아닌 값으로 넘긴 것. ↑로 같은 입력을 다시 친다. temperature 0이라 실측에서는 항상 14:00이었다.
- 스킬 에이전트가 파일을 못 읽음: 스킬 폴더는 기동 때 /tmp/koog-skills로 복사된다. 재시작한다.
