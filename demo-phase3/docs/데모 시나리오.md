# 데모 시나리오

입력과 예상 답을 순서대로 적는다. 화면에는 슬라이드 대신 위키 문서(`Koog.md`)를 띄우고, 단계 이름은 그 문서의 절 이름과 같다. 할 말은 `발표 스크립트.md`에 있다. 답은 실측(Koog 1.3.0, qwen3:4b-instruct, temperature 0)이고 글자 단위로는 달라질 수 있다.

## 화면

iTerm 한 창을 좌우로 나눈다. 글꼴 18 이상.

| 창 | 명령 | 역할 |
|---|---|---|
| 왼쪽 (크게) | `koog` | 2번부터 끝까지. 한 세션 |
| 오른쪽 (작게) | `koog step1` | 1번. 끝나면 `exit`하고 강제 종료 명령을 쳐 둔다 |

`koog`는 /opt/homebrew/bin/koog. bootJar 뒤 jar를 띄우므로 기동에 10초쯤 걸린다. `❯`가 뜨면 준비된 것. `exit`로 끝낸다. ↑로 이전 입력을 다시 쓸 수 있다.

## 준비 (발표 10분 전)

```bash
# 1. 모델 웜업 (2시간 고정)
curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null

# 2. 지난 실행 상태 비우기 (체크포인트, 캘린더 파일)
rm -rf ~/git/spring-ai-study/demo-phase3/data
```

3. 오른쪽에 `koog step1`, `❯`가 뜨면 `안녕` 한 번.
4. 왼쪽에 `koog`, `❯`가 뜨면 `판교 사투리 1로 바꿔 줘: 안녕하세요` 한 번. (비서 이력에는 안 남는다)
5. 위키 문서(`Koog.md`)를 열어 둔다.

## 순서

### 1. 기본 에이전트 (문서 "1/6 기본 에이전트") · 오른쪽

```
❯ 2 더하기 3은?
5
```

끝나면 오른쪽에서 `exit`. 그리고 6번용 명령을 쳐 두고 Enter는 누르지 않는다.

```bash
pkill -9 -f 'profiles.active=harness'
```

### 2. 도구 (문서 "2/6 도구") · 왼쪽

```
❯ 내일 일정 알려줘
  assistant   LLM #1 메시지 2개 → 도구 호출 schedules(day=내일)
  assistant   schedules → 10:00 팀 싱크, 14:00 디자인 리뷰
  assistant   LLM #2 메시지 4개 → 답
내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.
```

보는 것: 모델이 도구를 고르고(`LLM #1`), 결과를 받고(`schedules →`), 그걸로 답했다(`LLM #2`).

### 3. 스킬 (문서 "3/6 스킬") · 왼쪽

```
❯ 판교 사투리 3으로 바꿔 줘: 내일 회식 오세요
  dispatch    → skill
  skill       __read_file__(path=…/pangyo-dialect/SKILL.md)
내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.
```

보는 것: 스킬 에이전트로 갔고, SKILL.md를 읽은 뒤 답했다. 10초 안쪽이면 정상.

### 4. 오케스트레이션 (문서 "4/6 오케스트레이션") · 입력 없음

2번의 `dispatch → assistant`와 3번의 `dispatch → skill` 줄을 가리킨다.

### 5. 챗 메모리 (문서 "5/6 챗 메모리") · 왼쪽

```
❯ 아까 말한 첫 번째 일정이 뭐였지?
  assistant   LLM #1 메시지 4개 (이력 2개) → 답
10:00 팀 싱크입니다.
```

보는 것: `(이력 2개)`. 도구 줄 없이 이력으로 답했다.

### 6. 퍼시스턴스, 중단 뒤 이어서 (문서 "6/6 퍼시스턴스 > 중단 뒤 이어서")

기본은 문서의 출력 블록으로 설명한다. 라이브로 할 때만 아래대로.

왼쪽:
```
❯ 내일 일정 알려 주고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘
  assistant   LLM #1 메시지 6개 (이력 4개) → 도구 호출 schedules(day=내일)
  assistant   schedules → 10:00 팀 싱크, 14:00 디자인 리뷰
```
`schedules →` 줄이 보이면 오른쪽에서 Enter. 왼쪽이 `killed`로 끝난다.

왼쪽에서 다시 `koog`:
```
  persistence 중단된 실행 발견, verify 다음부터 이어감
  assistant   LLM #1 메시지 8개 → 답
내일의 일정은 다음과 같습니다: …
```

보는 것: 재시작하자마자 이어받았고, 도구 줄 없이 모델 호출 하나로 끝났다.
놓쳤으면: 답이 끝난 뒤 죽인 것이라 재개할 게 없다. 같은 입력으로 다시.

### 7. 퍼시스턴스, 롤백 (문서 "6/6 퍼시스턴스 > 롤백과 반대 도구") · 왼쪽

```
❯ 내일 14시에 치과 추가해 줘
  assistant   LLM #1 … → 도구 호출 add(day=내일, time=14:00, title=치과)
  assistant   add → 추가됨: 내일 14:00 치과
  assistant   검증: 14:00 치과 겹침 (14:00 디자인 리뷰) → 도구 실행 전 체크포인트로 롤백
  assistant   롤백 뒤 내일 일정: 10:00 팀 싱크, 14:00 디자인 리뷰
내일 14:00은 이미 디자인 리뷰 시간이라 치과 일정을 추가하지 않았습니다.
```

보는 것 셋:
- `add → 추가됨`: 도구가 실제로 돌았다.
- `롤백 뒤 내일 일정`에 치과가 없다: remove는 코드에 없고 Koog가 불렀다. 트레이스에는 안 찍힌다.
- 모델 호출은 한 번뿐이다.

### 8. 즉흥 입력 (문서 "Spring AI와 다른 점" 뒤) · 왼쪽

| 입력 | 답 |
|---|---|
| `두 번째 일정은 몇 시였지?` | `14:00 디자인 리뷰입니다.` |
| `내일 16시에 치과 추가해 줘` | `내일 16:00 치과 일정이 추가되었습니다.` (겹치지 않아 롤백 없음) |
| `내일 일정 알려줘` | `10:00 팀 싱크, 14:00 디자인 리뷰, 16:00 치과` |
| `내일 10시에 운동 추가해 줘` | `내일 10:00은 이미 팀 싱크 시간이라 운동 일정을 추가하지 않았습니다.` |
| `모레 일정은?` | `모레는 일정이 없습니다.` |
| `내 이름은 준이야` 뒤에 `내 이름이 뭐지?` | `당신의 이름은 준이에요.` |
| `판교 사투리 7로 바꿔 줘: 점심 같이 먹어요` | `점심 같이 먹고자 합니다. 싱크해 주세요.` |
| `판교 사투리 7로 일정 공지 만들어 줘` (일정 답 직후) | 직전 답을 공지로 바꿈 |
| `오늘 점심 뭐 먹을까?` | 도구 없이 비서가 답함 |
| `판교사투리란?` | SKILL.md를 읽고 강도 1~11 요약 |

청중에게 미리 말할 규칙:
- "판교 사투리"가 들어가면 스킬 에이전트로 간다. 콜론이 있으면 콜론 뒤를, 없으면 직전 비서 답변을 바꾼다. 강도는 꼭 적고 공지는 7.
- 캘린더는 가짜다. "내일"에만 두 건 있다.
- 한 줄에 한 가지만.

## 질문 대비: 체크포인트가 있을 때와 없을 때 (실측)

"메시지를 DB에 두면 되는 것 아닌가"에 답하는 비교. 코드 변경 없이 된다.

**A. 있을 때**
```
❯ 내일 16시에 치과 추가하고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘
  assistant   add → 추가됨: 내일 16:00 치과        ← 여기서 pkill -9
$ koog
  persistence 중단된 실행 발견, verify 다음부터 이어감
  assistant   LLM #1 메시지 4개 → 답
```
add는 한 번만 돌았다. `cat data/koog-calendar.txt`에 16:00 치과 한 건.

**B. 없을 때** (죽인 뒤 `rm -rf demo-phase3/data/koog-checkpoints`)
```
❯ 내일 17시에 미용실 추가하고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘
  assistant   add → 추가됨: 내일 17:00 미용실      ← 여기서 pkill -9, 체크포인트 삭제
$ koog
❯ (재개 줄 없음. 같은 입력을 다시 넣는다)
  assistant   add → 추가됨: 내일 17:00 미용실      ← 두 번째 실행
  assistant   검증: 17:00 미용실 겹침 (17:00 미용실) → 도구 실행 전 체크포인트로 롤백
```
요청을 처음부터 다시 돌렸고 부작용 있는 도구가 다시 돌았다. 검증 노드가 중복을 잡았을 뿐이다.

한 줄: 저장 위치(파일, DB)는 바꿔 끼우는 것. 차이는 저장 내용(어느 노드까지 끝났는지와 그 출력), 저장 시점(노드마다 자동), 이어받는 주체(같은 runId로 run하면 Koog).

## 실행 기록 줄

| 줄 | 뜻 |
|---|---|
| `dispatch → …` | 라우터가 보낸 곳. skill 또는 assistant |
| `LLM #n 메시지 N개 → 결정  시간` | 모델 호출 하나. 결정은 "도구 호출 이름(인자)" 아니면 "답". "(이력 M개)"는 챗 메모리가 실어 준 앞 대화 수 |
| `도구이름 → 결과` | 도구가 돌려준 값 |
| `검증: …`, `롤백 뒤 …` | 비서 전략의 verify, reject 노드가 찍는 줄 |
| `persistence 중단된 실행 발견 …` | 기동 때 완료 표시 없는 체크포인트를 찾음 |

## 어긋날 때

| 증상 | 원인과 대처 |
|---|---|
| `❯`가 안 뜸 | Ollama나 모델. 준비 1번부터 |
| 기동하자마자 `중단된 실행 발견`, 또는 2번 답이 두 건이 아님 | 지난 `data/`가 남은 것. `exit` 뒤 `rm -rf demo-phase3/data`, 다시 `koog` |
| 스킬 요청이 비서로 감 | "판교사투리"가 들어 있어야 한다(띄어쓰기 무관) |
| 비서가 일정을 지어냄 | 이력이 네댓 개 넘으면 4B가 도구를 건너뛸 수 있다. `exit` 뒤 `koog`로 이력을 비우고 2번부터 |
| 같은 추가 요청을 두 번째 넣었는데 "추가됨"만 답함 | 이력의 앞 답을 되풀이한 것. 다른 제목이나 시각으로 |
| 7번에서 롤백 없이 그냥 추가됨 | add 인자가 14:00이 아님. ↑로 같은 입력을 다시 |
| 6번 틈을 놓침 | 재개할 게 없다. 같은 입력으로 다시 |
