# 데모 시나리오

터미널에서 손이 할 일만 적는다. 할 말은 `발표 스크립트.md`에 있다. 출력은 전부 실제로 돌려 받은 것(Koog 1.3.0, qwen3:4b-instruct, temperature 0). 모델 출력이라 글자 단위로는 달라질 수 있고, 아래 "어긋날 때"에 대처를 적었다.

## 실행 명령

| 명령 | 프로필 | 코드 | 쓰는 장 |
|---|---|---|---|
| `koog step1` | step1 | Harness07.kt: AIAgent 하나와 readLine 루프 | 7장 |
| `koog` | harness | Harness12.kt: dispatchRouter + 비서(캘린더, 챗 메모리, 체크포인트) + 스킬 에이전트, 전부에 이벤트 트레이스 | 8~12장, 14장 |

`koog`는 /opt/homebrew/bin/koog. 안에서 `./gradlew bootJar` 뒤 `java -jar … --spring.profiles.active=<프로필>`을 실행한다. 기동은 약 10초, `❯` 프롬프트가 뜨면 준비된 것이다. 종료는 `exit` 또는 Ctrl-D.

터미널 2(harness)는 JLine이라 ↑로 이전 입력을 다시 쓸 수 있다. 터미널 1(step1)은 readLine이라 ↑가 안 된다.

## 준비 (발표 10분 전)

1. Ollama 확인과 모델 웜업. 2시간 동안 메모리에 고정된다.
   ```bash
   curl -s localhost:11434/api/tags | grep -o qwen3:4b-instruct
   curl -s localhost:11434/api/chat -d '{"model":"qwen3:4b-instruct","messages":[{"role":"user","content":"안녕"}],"stream":false,"keep_alive":"2h"}' -o /dev/null
   ```
2. 체크포인트 폴더를 비운다. 리허설에서 죽인 실행이 남아 있으면 기동하자마자 자동 재개된다.
   ```bash
   rm -rf /tmp/koog-checkpoints
   ```
3. 터미널 1에서 `koog step1`. `❯`가 뜨면 `안녕` 한 번 쳐서 JVM을 데운다. 답은 무시. 7장 뒤에는 `exit`로 나와서 12장용 명령을 쳐 둔다(Enter는 누르지 않는다).
   ```bash
   pkill -9 -f 'profiles.active=harness'
   ```
4. 터미널 2에서 `koog`. `❯`가 뜨면 `판교 사투리 1로 바꿔 줘: 안녕하세요` 한 번. 스킬 에이전트로 가서 파일 읽기까지 데워지고, 비서 세션(demo) 이력에는 남지 않는다. 비서 쪽 질문으로 데우면 11장 이력에 섞이니 피한다.
5. 슬라이드를 file://로 열고 #1 확인. 터미널 글꼴은 슬라이드 코드와 비슷한 크기로.
6. 아래 입력 문장을 복사해 둔다. 띄어쓰기까지 그대로.

## 진행

| 장 | 터미널 | 입력 | 답(실측) |
|---|---|---|---|
| 7 | 1 | `2 더하기 3은?` | `5` |
| 8 | 2 | `내일 일정 알려줘` | `내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.` |
| 9 | 2 | `판교 사투리 3으로 바꿔 줘: 내일 회식 오세요` | `내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.` |
| 9 여유 | 2 | `판교 사투리 11로 바꿔 줘: 내일 회식 오세요` | `… 참석 여부는 지라에 티켓으로 끊어 주시면 린하게 팔로업하겠으며, 불참 사유는 다음 회고에서 레슨런으로 공유 부탁드립니다.` |
| 10 | 입력 없음 | 8장은 assistant로, 9장은 skill로 갈린 dispatch 줄을 가리키며 말함 | |
| 11 | 2 | `아까 말한 첫 번째 일정이 뭐였지?` | `10:00 팀 싱크입니다.` |
| 12 | 2 → 1 → 2 | 아래 "12장 절차" | 재시작 뒤 자동으로 답을 마저 냄 |
| 14 | 2 | 청중 즉흥 입력 | 아래 후보 |

터미널 2는 8장부터 끝까지 한 세션이다. 11장의 답은 8장의 답을 이력에서 꺼낸 것이라, 중간에 하네스를 재시작하면 8장 입력을 먼저 다시 쳐야 한다. 12장에서 재시작하면 11장까지의 대화 이력은 비는데(인메모리 저장소), 그 뒤 14장 즉흥 입력에는 영향이 없다.

스킬 요청(9장)은 카탈로그 확인, 파일 읽기, 변환으로 모델을 두 번 부르니 가장 오래 걸린다. 10초 안쪽이면 정상이다.

## 흐린 줄 읽는 법

답 위에 흐리게 찍히는 줄은 하네스가 Koog EventHandler로 남기는 기록이다(Trace.kt). 8장부터 11장까지 실제 화면:

```
❯ 내일 일정 알려줘
  dispatch    → assistant
  assistant   LLM 호출 (메시지 2개)
  assistant   schedules(day=내일) → 10:00 팀 싱크, 14:00 디자인 리뷰
  assistant   LLM 호출 (메시지 4개)
내일은 10:00 팀 싱크, 14:00 디자인 리뷰가 있습니다.
❯ 판교 사투리 3으로 바꿔 줘: 내일 회식 오세요
  dispatch    → skill
  skill       LLM 호출 (메시지 2개)
  skill       __read_file__(path=/tmp/koog-skills/pangyo-dialect/SKILL.md) → 2,047자
  skill       LLM 호출 (메시지 4개)
내일 회식 오세요 → 내일 회식 공유 드리고, 참석 여부는 편하게 싱크해 주세요.
❯ 아까 말한 첫 번째 일정이 뭐였지?
  dispatch    → assistant
  assistant   LLM 호출 (메시지 4개)
10:00 팀 싱크입니다.
```

- `dispatch → …`: 라우터 전략이 들어간 노드. 판교 사투리는 skill, 나머지는 assistant (10장).
- `LLM 호출 (메시지 N개)`: 모델에 보낸 메시지 수. 도구 왕복이면 2개에서 4개로 늘고(8장), 비서 세션은 턴마다 2개씩 쌓인다(11장 이후 4, 6, 8…).
- `도구이름(인자) → 결과`: 도구 호출. 11장 턴에는 이 줄이 없다. 이력에서 답했다는 뜻이다.
- `persistence 중단된 실행 발견, … 다음부터 이어감`: 기동 때 완료 표시 없는 체크포인트를 찾았다는 뜻(12장).
- 터미널 1(`koog step1`)에는 이 줄이 없다. 7장과의 대비가 그 자체로 하네스 설명이다.

## 12장 절차: 강제 종료와 재개

1. 터미널 2에 입력: `내일 일정 알려 주고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘`. 답이 길어서 둘째 모델 호출이 몇 초 걸린다. 그 사이가 죽일 틈이다.
2. 흐린 줄 `assistant   schedules(day=내일) → …`가 찍히면 터미널 1에서 미리 쳐 둔 `pkill -9 -f 'profiles.active=harness'`에 Enter. 터미널 2가 `killed`로 끝난다. Ctrl-C는 JVM이 정리 종료를 하는 동안 모델 호출이 끝나 버려서 중단이 안 된다. 반드시 `-9`.
3. 터미널 2에서 `koog`. `❯`보다 먼저 아래 줄이 찍히고 답이 이어진다.

실제 화면:

```
❯ 내일 일정 알려 주고, 일정마다 준비할 것을 다섯 가지씩 이유와 함께 제안해 줘
  dispatch    → assistant
  assistant   LLM 호출 (메시지 2개)
  assistant   schedules(day=내일) → 10:00 팀 싱크, 14:00 디자인 리뷰
  assistant   LLM 호출 (메시지 4개)
[1]    63747 killed     java -jar …
$ koog
  persistence 중단된 실행 발견, nodeExecuteTool 다음부터 이어감
  assistant   LLM 호출 (메시지 4개)
1. **10:00 팀 싱크**
- 준비할 것: 노트북, 펜, 블루투스 헤드폰 (회의 중 소리가 들리기 위해)
…
❯
```

죽인 시점에 체크포인트는 둘(nodeCallLLM, nodeExecuteTool)이고 완료 표시가 없다. 재시작한 하네스는 그 다음 노드부터 돌려서 모델 호출 한 번으로 끝낸다. 도구는 다시 부르지 않는다. `ls /tmp/koog-checkpoints/checkpoints/demo`로 파일을 보여줘도 된다.

틈을 놓쳐 답이 끝난 뒤 죽였다면: 재시작해도 재개할 게 없다(완료 표시가 있음). 같은 입력으로 한 번 더 시도한다. 두 번 놓치면 슬라이드의 출력 블록으로 설명한다. 같은 캡처다.

## 14장 즉흥 입력 후보 (실측 통과)

| 입력 | 출력 | 보여주는 것 |
|---|---|---|
| `두 번째 일정은 몇 시였지?` | `14:00 디자인 리뷰입니다.` | 이력에서 답함 (12장 재시작 뒤에는 8장 입력을 먼저 다시 친다) |
| `내 이름은 준이야` 뒤에 `내 이름이 뭐지?` | `안녕하세요, 준이님. 어떻게 도와드릴까요?` 뒤에 `당신의 이름은 준이에요.` | 도구 없이 기억만으로 답함 |
| `판교 사투리 7로 바꿔 줘: 점심 같이 먹어요` | `점심 같이 먹고자 합니다. 싱크해 주세요.` | 스킬 강도 중간 |
| `오늘 일정이 있나?` 뒤에 `판교 사투리 7로 일정 공지 만들어 줘` | `오늘은 10:00 팀 싱크, 14:00 디자인 리뷰를 진행하고자 합니다. … 린하게 팔로업 …` | 비서 답변을 스킬이 이어받음. 11은 예시 문구가 섞일 수 있음 |
| `오늘 점심 뭐 먹을까?` | `점심은 카페에서 커피와 토스트를 먹는 걸 추천해요!` | 일정 아닌 질문은 도구 없이 비서가 답함 |
| `판교사투리란?` | SKILL.md를 읽고 강도 1~11 설명을 요약해 답함 | 스킬 요청은 띄어쓰기와 무관하게 스킬 에이전트로. 질문도 파일을 읽고 답함 |

청중에게 미리 말해 둘 규칙 둘. "판교 사투리"가 들어간 문장은 스킬 에이전트로 간다. 스킬 에이전트는 대화 이력이 없고, 대신 직전 비서 답변이 "바꿀 원문"으로 붙어 넘어간다. 그래서 "오늘 일정이 있나?" 뒤에 "판교 사투리 7로 일정 공지 만들어 줘"가 된다. 콜론이 있으면 콜론 뒤 문장을 바꾸고, 없으면 직전 답변을 바꾼다. 강도는 꼭 적고, 공지는 7을 권한다. 11은 SKILL.md의 예시 문구가 섞여 없는 사실(야근, 순연)이 붙을 때가 있다. 안 적으면 원문을 그대로 돌려준다. 나머지 문장은 비서로 가고 기억이 있으며, 일정 질문이면 캘린더 도구를 부른다. 캘린더는 날짜와 무관하게 같은 두 건을 돌려주는 발표용 가짜다.

실측(강도 11, 직전 답변이 오늘 일정일 때):

```
❯ 판교 사투리 11로 일정 공지 사항 만들어줘
  dispatch    → skill
  skill       LLM 호출 (메시지 2개)
  skill       __read_file__(path=/tmp/koog-skills/pangyo-dialect/SKILL.md) → 2,047자
  skill       LLM 호출 (메시지 4개)
오늘의 일정은 다음과 같습니다:
- 10:00 팀 싱크
- 14:00 디자인 리뷰

→ 금일 팀 싱크와 디자인 리뷰에 여러분을 초대합니다. 참여 여부는 지라에 티켓으로 끊어 주시면 린하게 팔로업하겠으며, 불참 사유는 다음 회고에서 레슨런으로 공유 부탁드립니다. …
```

4B 모델이라 긴 문장, 영어 섞인 문장, 여러 요청을 한 줄에 넣은 문장은 흔들린다. 한 줄에 한 가지만 받는다.

## 어긋날 때

- `❯`가 안 뜸: Ollama가 꺼졌거나 모델이 없다. 준비 1번을 다시 한다.
- 기동하자마자 `persistence 중단된 실행 발견`이 찍힘: 리허설에서 죽인 실행이 남은 것. 그대로 두면 답을 마저 내고 끝나니 무시해도 되고, 깔끔히 하려면 `exit` 뒤 `rm -rf /tmp/koog-checkpoints`, 다시 `koog`.
- 스킬 요청이 비서로 감: 입력에 "판교사투리"가 들어 있어야 한다(띄어쓰기는 무관). "판교 말투"처럼 다른 말은 비서로 간다.
- "뭐 할 수 있어?"에 비서가 스킬을 모른다고 답함: 설계상 그렇다. 스킬 이름을 대라고 안내한다("판교사투리란?"). 비서 프롬프트에 카탈로그를 넣으면 말투가 흔들려 뺐다.
- 콜론 규칙: 스킬 요청에 콜론(:)이 있으면 그 뒤 문장을 바꾸고, 없으면 직전 비서 답변을 바꾼다. "판교 사투리 7로 일정 공지 만들어 줘"는 후자.
- 스킬 에이전트가 파일을 못 읽음: 스킬 폴더는 기동 때마다 /tmp/koog-skills로 복사된다. `exit` 후 `koog`를 다시 띄운다.
- 비서가 일정을 지어냄: 4B가 가끔 도구를 안 부른다. 같은 입력을 ↑로 한 번 더 보낸다.
- 대화가 꼬임: `exit` 후 `koog`. 대화 이력은 메모리에만 있어 재시작하면 비워진다. 11장 전이라면 8장 입력부터 다시.
- 7장 터미널 1이 느림: 첫 요청은 JVM 워밍업이 섞인다. 준비 3번을 건너뛰었을 때 생긴다.
